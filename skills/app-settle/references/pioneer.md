# The Pioneer path — read on a Pioneer answer, or a platform typed from outside the list

**Pioneer makes a platform this toolkit has not run on a visible choice with a stated cost.** Six rules:

1. **Name what does not exist, first.** Three lines before anything continues: no rubric row to read the options from, no repo that has run this platform under this plugin, and the guard line below. One confirmation; declining routes back to a Ready platform. The absence of templates is **not** one of the lines — no platform has any.
2. **Storage decides the guard line.** The destructive guard matches SQL syntax, so any SQL store — Supabase, SQLite, Room, Drift — stays covered wherever the app runs. A non-SQL store is not covered: say so before question 6 is answered, as that question rules.
3. **Assemble by live research the stack questions the tables cannot serve** — framework or language where the platform leaves a choice, distribution instead of hosting, project layout: real current options, more than two, one marked recommendation, a one-sentence consequence each, never from memory alone. One subagent pass (`SKILL.md`, What a run costs) returns the options per question with their sources; the recommendation is verified, every other option marked `unverified` until picked. These replace questions 3 and 4; questions 5–7 still run — the database does not care where the app runs, only the guard line does.
4. **The scaffold is minimal and honest**: the platform's own init command, then `.claude/settings.json`, `CLAUDE.md`, and `AGENTS.md` — the same three files a Ready platform receives. The platform's own config and deploy path are still owed; list them in the close block.
5. **The Surface row in `docs/product.md` records `Platform: <name> (pioneer)`** — the marker later skills read to know this repo runs ahead of the toolkit's rubric.
6. **The Proof profile is proven, not asserted.** Its shape lives in `docs-format`'s shapes. Execute each line once before writing it — run the run command, take one capture; a line not executed is written `[needs verification]`, and the skills that read it report instead of claim.

## Promotion — raising a row's status

**After one real repo ships on a Pioneer platform, offer the promotion**: a row in the rubric of `stack-questions.md`. **Not ready** or **Pioneer** becomes **Ready** only once two things exist:

1. **A named migration or deploy path**, written out once in a real repo, precise enough for the session that chooses this row to follow. Not a template — this plugin ships none for any stack, and no file is copied anywhere.
2. **A statement of guard coverage.** The `kaizn` destructive guard matches SQL syntax in the `query`, `command`, `sql`, and `statement` fields. It survives any SQL database and **does not apply** to non-SQL storage — and a hook that finds nothing does not report, it stays quiet. A stack outside the guard's reach must bring a replacement, or make the guard announce its own inapplicability once at session start.

Without item 2, do not raise the status: a repo that looks protected while it is not is more dangerous than one that is plainly unprotected.
